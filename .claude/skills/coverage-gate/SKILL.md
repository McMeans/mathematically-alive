# Black-box coverage gate

The gate measures line coverage of `src/core` reached **only** by `tests/blackbox`. Those tests import from `@/core` (the public entry point, `src/core/index.ts`), so code counts as covered only if public behavior reaches it.

## Run

```bash
.claude/skills/coverage-gate/gate.sh        # default threshold 85%
.claude/skills/coverage-gate/gate.sh 90     # custom threshold
```

Exit 0 = pass. Exit 1 = tests failed or coverage below threshold.

## When it fails

1. If tests failed, fix the code or the test. Do not delete or weaken an assertion to go green without saying why.
2. If coverage is short, read the `Uncovered Line #s` column in the printed table.
3. For each gap, work out which **public input** reaches it (a schedule fixture, a set of game results, locked what-ifs, a seed) and add a test in `tests/blackbox` that drives that input and asserts on public output.
4. Never import from a file other than `@/core` in a black-box test, never export something just to test it, and never mock internals. If a line can't be reached from the public API, it's likely dead code. Report it instead of covering it.
5. Data fixtures go in `fixtures/` and are generated by a script there, never hand-edited.

## Ratchet

When coverage sits well above the threshold, raise the default in `gate.sh` (`COVERAGE_THRESHOLD:-NN`) to just under the new number. Never lower it without the user agreeing.

## Report

Give the line percentage, pass/fail, and any tests you added.
